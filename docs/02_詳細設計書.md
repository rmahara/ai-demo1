## 1. コントローラー設計

### 1.1 OrdersController（受注管理）

**名前空間**: `ConcreteShipping.Controllers`
**ルート**: `/Orders`

| アクション | HTTPメソッド | URL | 説明 |
|-----------|-------------|-----|------|
| Index | GET | /Orders | 受注一覧（検索・ページング） |
| Create | GET | /Orders/Create | 受注入力フォーム表示 |
| Create | POST | /Orders/Create | 受注登録 |
| Edit | GET | /Orders/Edit/{id} | 受注編集フォーム表示 |
| Edit | POST | /Orders/Edit/{id} | 受注更新 |
| Delete | POST | /Orders/Delete/{id} | 受注削除（論理削除） |
| Details | GET | /Orders/Details/{id} | 受注詳細表示 |

#### Create POST 処理フロー

```
1. [Controller] ModelState.IsValid チェック
   → 失敗: ビューを再表示（バリデーションエラー）
2. [Controller] OrderService.CreateAsync(viewModel) 呼び出し
3. [Service] Order エンティティ生成
   - Status = OrderStatus.Received
   - CreatedAt / UpdatedAt = DateTime.UtcNow
4. [Repository] OrderRepository.AddAsync(order)
5. [EF Core] INSERT INTO Orders
6. [Controller] RedirectToAction("Index")
```

#### バリデーション仕様（OrderCreateViewModel）

| フィールド | ルール |
|-----------|--------|
| CustomerId | 必須、存在チェック |
| MixId | 必須、存在チェック |
| Quantity | 必須、0.1〜999.9、小数第1位まで |
| OrderType | 必須、0または1 |
| DeliveryDate | 必須、受注日以降 |
| DeliveryAddress | 任意、最大200文字 |
| Note | 任意、最大500文字 |

## 4. データ転送オブジェクト（DTO / ViewModel）

### 4.1 OrderCreateViewModel

```csharp
public class OrderCreateViewModel
{
    [Required(ErrorMessage = "得意先は必須です")]
    public int CustomerId { get; set; }

    [Required(ErrorMessage = "配合は必須です")]
    public int MixId { get; set; }

    [Required]
    [Range(0.1, 999.9, ErrorMessage = "数量は0.1〜999.9の範囲で入力してください")]
    public decimal Quantity { get; set; }

    [Required]
    public OrderType OrderType { get; set; }

    [Required(ErrorMessage = "納入日時は必須です")]
    [FutureDate(ErrorMessage = "納入日時は受注日以降を指定してください")]
    public DateTime DeliveryDate { get; set; }

    [MaxLength(200)]
    public string? DeliveryAddress { get; set; }

    [MaxLength(500)]
    public string? Note { get; set; }

    // 選択肢用
    public IEnumerable<SelectListItem> Customers { get; set; } = [];
    public IEnumerable<SelectListItem> Mixes { get; set; } = [];
}
```

## 6. エラーハンドリング設計

### 6.1 例外種別と対応

| 例外 | 発生箇所 | 対応 |
|------|---------|------|
| EntityNotFoundException | Service層 | 404ページ表示 |
| BusinessRuleException | Service層 | エラーメッセージをViewBagに設定し入力画面再表示 |
| DbUpdateException | Repository層 | ログ記録後、500ページ表示 |
| UnauthorizedAccessException | Controller層 | 403ページ表示 |

### 6.2 グローバル例外ハンドラー

`Program.cs` にて `UseExceptionHandler("/Error")` を設定。
開発環境のみ `UseDeveloperExceptionPage()` を使用。

## 7. セキュリティ設計

### 7.1 XSS対策

- Razor View ではデフォルトの HTML エンコード（`@変数`）を使用
- `@Html.Raw()` の使用を禁止（レビューで検出）
- Content Security Policy ヘッダーを設定

### 7.2 CSRF対策

- `[ValidateAntiForgeryToken]` を全POSTアクションに付与
- `@Html.AntiForgeryToken()` をフォームに自動付与（TagHelper使用）

### 7.3 SQLインジェクション対策

- EF Core パラメーター化クエリのみ使用
- 生SQLは禁止（`FromSqlRaw` 使用時は必ずパラメーター化）

### 7.4 認可

- 全コントローラーに `[Authorize]` 付与
- ロールベース制御: `[Authorize(Roles = "Admin")]`

## 8. パフォーマンス設計

### 8.1 N+1クエリ対策

EF Core の `Include` を使用して関連エンティティを一括ロード。

```csharp
// 悪い例（N+1）
var orders = await _context.Orders.ToListAsync();
foreach (var o in orders) { var c = o.Customer.Name; } // N+1

// 良い例
var orders = await _context.Orders
    .Include(o => o.Customer)
    .Include(o => o.Mix)
    .AsNoTracking()
    .ToListAsync();
```

### 8.2 ページング

一覧画面は `Skip` / `Take` によるページング実装（1ページ20件）。

### 8.3 非追跡クエリ

参照系クエリには `.AsNoTracking()` を付与しパフォーマンスを向上。
