## 1. テスト方針

### 1.1 結合テストの目的

単体テストで検証済みのコンポーネントを組み合わせ、以下を検証する。

- 画面 → Controller → Service → Repository → DB の一連の処理フロー
- 業務シナリオ全体の動作整合性
- 画面遷移とリダイレクトの正確性
- DBへのデータ永続化の正確性

### 1.2 テスト環境

| 項目 | 内容 |
|------|------|
| テストDB | SQLite インメモリDB（EF Core UseInMemoryDatabase） |
| テストフレームワーク | xUnit + ASP.NET Core TestServer |
| ブラウザ自動化 | 画面操作テストは対象外（E2Eは別フェーズ） |

### 1.3 テストデータ方針

- 各テストクラスの `IClassFixture` で初期データを投入
- テストは独立して実行可能（順序依存なし）
- テスト後はDBをリセット
